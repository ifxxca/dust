## 1. Urutan delivery dan batas pekerjaan

Urutan dependency: **Review/Gate 0 → M1 → M2 → M3 → M4 → M5**. M1 memberi transport dan sesi perangkat; M2 memberi visit authoritative; M3 memerlukan visit COLLECTED untuk POP; M4 membutuhkan POP final untuk handover. QA perangkat dan baseline performa mulai sejak M1, bukan menunggu akhir.

Hanya dua dokumen dibuat pada tahap audit. Semua nama file/module baru dalam plan adalah **perkiraan usulan**, bukan file yang sudah tersedia. Penambahan dependency, folder native dan perubahan transport menunggu review. Tidak menduplikasi business logic ke TypeScript atau membuat mobile service/database operasional baru.

Tidak ada estimasi kalender/effort yang dianggap final sebelum keputusan perangkat, vault, dependency, personel dan review. Setiap milestone selesai berdasarkan evidence acceptance dan gate, bukan sekadar UI tersedia.

### Gate 0 — Review desain

1. Review technical design dan plan oleh Produk/Operasional, Backend, Mobile, QA/Security.
2. Sepakati facade `/api/mobile/v1` yang memanggil domain existing, envelope/version guards, read-only submission lookup, dan bukti privat bearer.
3. Tutup OD-02, OD-08, pilihan logout M1 OD-05 serta OD-10 sebelum membangun foundation; identifikasi target fleet awal OD-01 dan identity build OD-06.
4. Sepakati bahwa gap verifikasi/closure Pickup Staff pada backend tidak diperbaiki diam-diam. Facade V1 membatasi transport ke operasi in-scope; pengetatan hak backend web memerlukan pekerjaan terpisah.
5. Beri persetujuan memulai implementasi. Dokumen selesai bukan persetujuan tersebut.

### Acceptance criteria

1. APK membuka packaged shell tanpa Laravel/Inertia HTML bootstrap; mobile bundle tidak menarik runtime Inertia atau web app bootstrap.
2. Credential valid aktif + role channel yang disetujui menghasilkan token perangkat dengan expiry; wrong/inactive login tidak menghasilkan token dan memakai error aman.

6. Mine sesuai scope user, Available hanya kandidat backend, detail kandidat tidak membocorkan field yang omitted; unauthorized task 404.
7. Query/filter dan pagination sesuai contract; ID tidak duplikat saat page merge; filter/session change membersihkan list lama. Network error tidak terlihat sebagai empty success.
8. Foreground refresh memakai timezone API; mutation UI yang belum tersedia tidak ditawarkan. Login/logout web dan CSRF mutation web lolos regresi.

Gate M1 ditandatangani reviewer yang disepakati.

## 3. Mobile M2 — Takeover & Execution

### Scope

- Alias transport takeover, execution start, outcome, retry ke actions existing.
- Konfirmasi takeover dengan optional reason, old assignee/version; refresh Mine/Available.
- Start kunjungan online, GET task sesudah start untuk version baru; outcome COLLECTED/NO_PACKAGES beserta validation dan reason.
- Retry owner sesuai `can.retry`, reason dan version. Cancel tidak tersedia untuk Pickup Staff sesuai `ChangeTaskLifecycle`.
- Double-submit guard, local pending operation metadata sebelum send, timeout reconciliation task/visit/events; tidak auto-rebase atau auto-send setelah reconnect.

### Perkiraan file/module terdampak

- `routes/api.php` mobile allowlist/abilities; `PickupTaskController`, `PickupExecutionController`, `PickupLifecycleController` hanya adaptasi transport bila dibutuhkan, bukan mengganti domain rules.
- Existing `app/Actions/Pickup/{TakeOverTask,StartPickup,RecordPickupVisit,ChangeTaskLifecycle}.php`, Requests takeover/outcome dan Resources task/visit direuse; perubahan domain **tidak direncanakan**.
- Review urutan visits untuk serializer `can.retry`: relasi existing belum ordered walaupun resource memakai last(). Bila perlu ordering ID eksplisit, itu perbaikan determinisme query dengan regression multi-visit, bukan aturan retry baru.
- `resources/mobile/src/features/tasks`, `features/execution`, `api`, `state`, `platform`, metadata recovery store.
- `tests/Feature/MobileExecutionTest.php`; perluasan regression existing bila boundary transport terkena; generated Wayfinder.

### Dependencies / keputusan gate

- M1 auth/API capabilities dan typechecking lulus; server timestamps dan task versions telah dipahami.
- Recovery operation metadata memakai persistence aman yang disetujui OD-10, terisolasi account; belum menjadi queue mutation offline.
- Lingkungan MySQL test disposable tersedia untuk concurrency. Test existing membuat database baru; jangan dijalankan ke database produksi atau credential terbatas tanpa persiapan.

### Acceptance criteria

1. Dua actor takeover bersamaan hanya satu mendapat ownership; expected old assignee/version mencegah overwrite; event taken_over tetap tercatat existing.
2. Previous assignee tidak dapat start/record/finalize setelah kehilangan ownership. Takeover setelah execution_started_at tidak diizinkan.
3. Start menambah visit/version tanpa memperkenalkan task status IN_PROGRESS. Replay unfinished start tidak membuat visit baru.
4. Outcome wajib sesuai enum; NO_PACKAGES wajib reason, status task tetap ASSIGNED. COLLECTED tidak berarti PICKED_UP.
5. Identical visit replay tidak membuat outcome ganda; payload berbeda setelah recorded ditolak. Retry mempertahankan visit lama dan memberi start baru hanya setelah otorisasi.
6. Timeout/5xx/abort ditandai uncertain; task/events dibaca sebelum menawarkan retry; perubahan version/ownership tidak otomatis direbase. Offline klik tidak menghasilkan success.

### Test scenarios

- Bearer facade: role/ability denied, inactive actor, non-owner, stale expected_version/assignee, started/ineligible task, prohibited takeover fields.
- Concurrent takeover dan takeover-vs-start: satu outcome authoritative; audit actor, version dan count benar. Gunakan MySQL concurrency test existing `PickupTakeoverConcurrencyTest.php` dan scenario worker yang relevan, bukan SQLite saja.
- Start dua kali, outcome dua kali identik/berbeda, NO_PACKAGES tanpa reason, retry sebelum/ sesudah NO_PACKAGES, retry stale, cancel oleh Pickup Staff forbidden melalui web baseline dan tidak terdaftar di facade.
- Android network diputus sesudah server commit start/outcome/takeover/retry, force-stop ketika request berjalan, refresh gagal, reauth pending operation, perubahan oleh web sebelum GET/POST.
- Baseline narrow `PickupExecutionTest.php`, `OperationalLifecycleTest.php`, `RetailPickupM1Test.php`; tambah test pada boundary yang belum tercakup, bukan salinan rule arrays.

### Definition of Done

Seluruh action mobile memakai existing action dan lock/version behavior; mutation feedback hanya sukses setelah acknowledgement/state terkonfirmasi. Concurrency MySQL dan narrow feature tests lulus, APK diuji pada koneksi buruk untuk execution flow; tidak ada duplicated visit/ownership atau silent cancel. State recovery bertahan restart, terdokumentasi dalam hasil review, typecheck/build web+mobile dan web execution regresi lulus. M2 gate selesai sebelum finalization M3.

## 4. Mobile M3 — POP Wizard

### Scope

### Dependencies / keputusan gate

- M2 visit COLLECTED dan recovery lulus; OD-04 TTL/quota/uncertain cleanup serta OD-05 logout/switch draft policy ditutup.
- OD-10 vault native dan selected plugin API sudah diuji; OD-01 perangkat termasuk behavior photo picker/camera vendor diuji; recovery callback dipasang sebelum membuka activity.

- OD-07 baseline upload, memory dan timeout mulai diukur; angka performance gate ditetapkan sebelum pilot, tidak mengarang SLA.

### Acceptance criteria

1. Quantity integer nonnegative <=1,000,000/kategori; total otomatis cocok server dan >0 untuk POP. Total nol menuju NO_PACKAGES workflow, bukan final POP.
2. Photo opsional maksimal empat, masing-masing <=5120 KiB JPEG/PNG/WebP; signature wajib PNG <=1024 KiB <=2000x1000 dan nonblank. HEIC ditangani sebelum upload.
3. Preview/replace/delete bukti bekerja; tanda saved lokal hanya muncul setelah manifest/file durable. Storage penuh menampilkan belum tersimpan, tidak merusak draft lama.
4. Restart normal/force-stop setelah saved memulihkan quantity/notes/step/foto/signature/key pada akun/environment yang sama. Hasil camera activity recovery masuk draft yang tepat; akun berbeda tidak membukanya.
5. Draft local tidak dianggap data server; no mutation offline atau auto-send saat reconnect. Preflight GET me/task/version/latest visit menolak stale/ownership lost/finalized task.
6. Finalisasi user-confirmed mengirim canonical multipart dan action existing. Task PICKED_UP, single proof, attachments dan audit hanya setelah commit; rollback evidence failure tidak meninggalkan POP separuh.
7. Timeout dan restart SENDING masuk UNCERTAIN. Lookup/GET atau safe immutable same-key replay mencegah duplicate; payload tidak dapat diedit selama attempt belum resolved.
8. Private evidence ditolak bagi user tanpa policy, di-fetch bearer binary; token tidak di URL/img raw. POP dan receipt status tampil terpisah; receipt UNKNOWN bukan gagal POP.
9. Cleanup mematuhi approved policy dan hanya sesudah commit/discard; pending evidence tidak terhapus otomatis. Upgrade schema tidak silently discard old draft.

### Test scenarios

- Bearer validation: negative/decimal/overflow/string invalid quantity, zero total, max boundary, photos lima/oversize/nonimage/HEIC, missing/blank/oversize/dimension signature, notes length.
- Existing `ProofOfPickupTest.php`: rollback storage, canonical integer strings, duplicate proof/key, stale and unauthorized, NO_PACKAGES cannot finalize. Tambah boundary bearer evidence/no-cookie test.
- Lookup: UUID tidak ada, actor lain, inaccessible task, matching key, key dari proof lain, GET error saat original POST masih berjalan. Jangan menjadikan 404 proof of non-commit.
- Same-key replay membutuhkan multipart valid sesuai request existing; test client mempertahankan file/checksum/key, server tidak membuat second record/event.
- Device: permission cancel/reject, app killed ketika camera, image content URI revoked, low memory saat empat file maksimum, portrait/keyboard/signature pointer cancel, storage full sebelum dan sesudah file rename, manifest corrupted/unsupported schema.
- Account A draft→logout/switch B→login A; token expiry/role loss saat review; server web finalizes terlebih dahulu; retry/new visit invalidates draft context.
- UAT-04, 06, 07, 08, 10, 11; POP commit tetapi SMTP response terlambat/hilang/receipt not configured. Background tidak memicu auto-finalisasi.

### Definition of Done

Semua acceptance termasuk native persistence/crash recovery lulus pada perangkat nyata, bukan browser preview saja. POP feature/regression dan bearer lookup/evidence tests lulus; private encrypted storage/backup exclusion direview. Uji timeout membuktikan satu proof dan tidak ada klaim receipt terkirim palsu. Draft retensi/logout decision telah diterapkan, quota/full-storage UX diuji, upload/memory baseline dicatat dalam hasil QA. Web POP/build tidak regresi; APK M3 reproducible; tidak ada bug critical/high integritas/evidence/draft terbuka.

## 5. Mobile M4 — Handover & History

### Scope

- Kandidat eligible handover lintas petugas dengan pagination fixed 20; create session, detail/status, DRAFT amend seluruh daftar anggota dengan reason/version.
- Persist immutable create submission key/selected task IDs sebelum send, lookup `kind=handover`, reconciliation amend melalui detail/events.
- Riwayat pickup dari `history=1`, handover CLOSED history, POP/evidence/revisions dan receipt status actual.
- Pickup Staff hanya menjalankan operasi in-scope: tidak ada UI/API facade verify, verification correction, reopen, close, POP correction, receipt resend atau management role lain.

### Perkiraan file/module terdampak

- `routes/api.php` alias handover; `HandoverController.php` dan `HandoverResource.php` route-context list adaptation; `MobileSubmissionController.php` extend lookup kind=handover.
- Existing `app/Actions/Handover/{CreateSession,AmendSession}.php`, `StoreHandoverRequest.php`, Handover models/migrations direuse tanpa mengubah eligibility, cross-staff access atau whole-list replacement.
- `resources/mobile/src/features/handover`, `features/history`, API DTO/pagination adapters, local immutable attempt metadata dan navigation.
- `tests/Feature/MobileHandoverTest.php`, lookup tests; existing `HandoverVerificationTest.php`, `HandoverListRefinementTest.php`, `OperationalLifecycleTest.php`, `OperationalCorrectionTest.php`, `PickupReceiptDeliveryTest.php` sesuai impact.

### Dependencies / keputusan gate

- M3 proof final dan evidence access lulus; OD-09 gap backend verify/close selesai direview. Scope mobile-only restrictions diterima atau perubahan rules dijadikan task terpisah.
- Contract kandidat berbeda dari resource pagination telah diterapkan; resource index alias tidak membocorkan items/full detail secara accidental.
- Recovery same-key create dan logout pending attempt sesuai OD-05; retention attempt ikut kebijakan approved.

### Acceptance criteria

1. Kandidat hanya task PICKED_UP + proof + tanpa handover item; lintas staff tetap tersedia. Tidak ada owner-only restriction atau feature search kandidat yang backend tidak mendukung.
2. Create 1..100 distinct tasks online mengembalikan DRAFT; same key/creator replay satu session, conflict task already-member tidak membuat double membership.
3. DRAFT editor memuat existing members dan kandidat; body mengandung keseluruhan desired task_ids, expected version dan reason. Non-DRAFT/stale session tidak diubah.
4. Concurrent create/amend/verification ditangani lock/version backend. User melihat conflict dan review ulang, bukan overwriting memakai latest version tanpa konfirmasi.
5. Timeout create dapat resolved lewat key dan session GET; original in-flight + replay key sama tetap satu session. Amend uncertain tidak otomatis menimpa edit pihak lain.
6. List/detail/history menunjukkan status, totals, differences, revision dan needs_review dari server. CLOSED tidak menyembunyikan discrepancy. POP final read-only dan receipt accepted/delivered dibedakan.
7. API mobile tidak menyediakan verification/closure endpoint; token mobile gagal mencoba route Retail/web secara langsung. Existing behavior web tidak berubah dari pembatasan channel.
8. History milik user mengikuti scope existing (termasuk current assigned owner); tidak mengklaim history seluruh task yang pernah dikerjakan actor jika backend tidak mendukung query tersebut.

### Test scenarios

- Cross-staff create, task unfinished/no proof/already member/nonexistent, duplicate/max IDs, wrong role/ability, key replay different creator.
- Amend menambah/menghapus members dengan whole-list replacement; existing member tetap dapat dipilih walau tidak ada dalam candidates; empty list, stale version, DRAFT→IN_VERIFICATION sesudah editor terbuka, task stolen by other session.
- MySQL concurrency create untuk membership yang sama dan amend terhadap session berubah; verifikasi tetap berlangsung lewat web dalam UAT untuk status transition.
- Timeout create response lost + app restart + lookup same actor; lookup actor lain 404; amend current IDs/event ambiguous tidak diikuti auto-submit.
- Riwayat NO_PACKAGES ASSIGNED, CANCELLED, PICKED_UP, OPEN/CLOSED handover, corrections effective values/revisions, needs_review; no configured receipt/UNKNOWN/ACCEPTED_BY_PROVIDER/DELIVERED.
- Private evidence setelah handover diuji mengikuti policy existing: operator dapat view handover task, bukan mengharapkan owner-only denial yang bertentangan kode.
- UAT-09, 11, 12 dan web verification regression; direct mobile verify/close/corrections/reopen forbidden/unregistered.

## 7. Strategi testing dan checks per milestone

Pilih coverage meaningful sesuai skill Testing Best Practices dan sibling tests. Feature tests memakai factory existing, state setup dari domain yang valid, assert response **dan** persisted record/version/audit/evidence ketika relevan. Jangan menulis tests yang hanya memeriksa string route atau menduplikasi array validation. Gunakan Artisan `make:test --pest <Name> --no-interaction`; nama tanpa prefix Feature, dan jangan menghapus tests existing.

Bearer boundary: uji token stored/expired/revoked, role/ability, auth:sanctum + personal-token check, no session fallback. Session `actingAs` existing tetap penting untuk regresi web tetapi tidak cukup untuk mobile. Tidak menambahkan package testing/browser diam-diam; native/manual test dan client test tooling disetujui pada OD-10.

MySQL concurrency berjalan di database disposable terisolasi sesuai `PickupTakeoverConcurrencyTest.php`; tidak menyentuh produksi. Test default SQLite in-memory cukup untuk banyak contracts, tidak untuk membuktikan row lock simultaneous requests. Existing concurrency test membuat/menghapus database sendiri; pastikan runner/credentials test benar sebelum menjalankannya.

Pada implementasi, jalankan affected file paling sempit dengan `php artisan test --compact <path>` atau Pest filter; rerun test setiap kali test/behavior terkait berubah. PHP yang dimodifikasi wajib `vendor/bin/pint --dirty --format agent`. Setelah feature tests pass, minta user menjalankan suite lengkap `php artisan test --compact` sesuai AGENTS; M5 tidak dianggap selesai tanpa evidence hasil full regression. Scope audit dokumen ini tidak mengharuskan menjalankan suite yang membuat data test.

Frontend checks existing `npm run types:check`, `npm run build`, dan checks mobile usulan wajib pass untuk milestone yang menyentuh shared/frontend. Jalankan `npm run check` sesuai cakupan/konvensi setelah lint configuration mengenali mobile; jangan memperbaiki file unrelated demi lint global tanpa alasan. Native build/sync dan actual device install masuk acceptance, bukan pengganti typecheck. Format/lint hanya pada scope perubahan yang disetujui.

### 10.3 Authentication/security minimum yang direkomendasikan

- **Token device:** UUID instalasi non-secret, bukan identitas terpercaya hardware. Gunakan standard Sanctum token table dan token name berformat terkontrol `mobile:<uuid>:<device-label>`, ability M1 `mobile:read`; lakukan replacement scoped user+UUID secara atomik setelah valid login. Tidak perlu device model/table/admin CRUD; metadata tambahan hanya bila kebutuhan nyata dibuktikan.
- **Login:** credential User existing, lowercase email dan hash check sesuai Fortify; aktif dan pickup_staff; safe generic error wrong/inactive credentials; login throttle mengikuti existing 5/min normalized email+IP. Token plaintext hanya diterima saat login dan dipersist terenkripsi. Tidak menyimpan password, tidak auto-retry login yang response-nya hilang. Re-login user-confirmed pada instalasi sama merevoke token sebelumnya.
- **Transport:** `/api/mobile/v1`, bearer-only + active-user + role-channel + ability, policy/resource existing tetap berlaku. Logout harus dapat mencabut current mobile token meski role berubah/nonaktif; tidak mencabut session web/perangkat lain. Cookie-only request tidak boleh lolos melalui fallback Sanctum. [Sanctum](https://laravel.com/framework/docs/13.x/sanctum).
- **Expiry/revoke:** 401 hapus credential/cache lokal, login ulang; 403 active/role denied mengunci akses dan membersihkan displayed data. Tidak mengasumsikan token claims masih memberikan hak setelah database role berubah. Password reset revoke mobile token belum tersedia existing; scope hardening OD-03 ditetapkan sebelum pilot.
- **Offline logout:** tombol server logout tidak menyatakan berhasil offline. Kunci lokal menulis locked flag durable bersama secure session sebelum menghapus memory/cache; locked state bertahan restart. Encrypted token yang sama hanya dapat dipakai untuk explicit completion logout, bukan GET/mutation bisnis. Reconnect tidak membuat worker/background revoke. 200 logout atau 401 current token invalid menyelesaikan cleanup; timeout/network error tetap terkunci. Account switch menunggu penyelesaian online; token yang hilang karena vault corrupt tetap bisa dicabut melalui support OD-03.
- **Vault:** satu secure session slot `{token,userId,environment,expiresAt,locked}`. Token terenkripsi app-private, key Keystore; pakai AES-GCM API platform dengan IV baru, fail closed bila key/write gagal; backup/transfer credential dikecualikan. UUID instalasi dapat menjadi setting non-secret. Jangan memperkenalkan framework enkripsi file foto, biometric flow atau multi-account token vault pada M1. ### 14.1 Reproduksi dan root cause

Error persis **“Data lokal belum dapat dibuka. Login ulang atau hubungi support; data tidak dihapus.”** direproduksi langsung di BlueStacks pada detail task QA. Informasi server muncul, execution dan POP gagal read lokal. Diagnostic native read hanya mengembalikan metadata akun/environment/expiry/locked dan error code; PAT tidak dicetak, file credential/draft tidak diekspor. Sesi native valid/unlocked, environment cocok dengan LAN yang disetujui, expiry masih mendatang dan format backend adalah ISO8601 **+00:00**.

`MobileLocalPlugin.scope()` memanggil `Instant.parse(expiresAt)` sebelum membaca repository. Pada Android13, parser ISO_INSTANT tersebut menolak offset Carbon: **DateTimeParseException at index19**. Semua exception scope/decrypt dibungkus sebagai LOCAL_READ_FAILED, sehingga terlihat sebagai kerusakan storage. Execution menahan aksi ketika recovery journal tidak dapat dibaca; POP loader terkena guard yang sama. Ini bukan bukti Keystore rusak atau capability server salah. Native ciphertext belum dibaca ketika expiry parser gagal.

BlueStacks kemudian tidak tersedia; sesuai jawaban user **“Lanjutkan dengan emulator terpisah dahulu”**, dibuat AVD khusus Retail_P0_API33/API33/Android13 di host SDK. APK/test diagnostic sebelum fix menghasilkan FAIL di runtime itu pada string `2026-10-14T17:34:18+00:00`. APK yang memakai `OffsetDateTime.parse(...).toInstant()` menghasilkan PASS, termasuk offset+07:00 dan penolakan expiry invalid. Root cause dibuktikan dengan negative/positive native execution, bukan asumsi dari screenshot. [Android13 parser source](https://android.googlesource.com/platform/libcore/+/refs/heads/android13-release/ojluni/src/main/java/java/time/format/DateTimeFormatterBuilder.java) mendukung trace tersebut. System image Android13 merupakan tooling host tambahan; bukan dependency aplikasi.

### 14.2 Perbaikan P0 dan recovery

- Native scope menerima ISO8601 ber-offset/Z tanpa mengubah durasi/token backend. Expiry tepat pada/sudah melewati deadline tetap ditolak. Namespace account+environment dan AAD tidak berubah.
- Error native dibedakan: session invalid/locked, scope denied, ciphertext/key tidak terbaca, storage tidak tersedia dan quota. Tidak membocorkan raw exception/key/evidence ke logs. HTTP404/5xx diberi pesan staf yang aman, status tetap tersedia untuk reconciliation; validation errors tetap dipertahankan.
- Read Keystore tidak menginisialisasi key baru. Write tidak membuat replacement key ketika ciphertext lama ada tetapi alias hilang. Tidak mereset alias, melemahkan enkripsi atau memperkenalkan plaintext fallback.
- Execution dan POP punya **Coba Baca Ulang**. Informasi task read-only tetap terlihat ketika storage lokal gagal. Journal sehat tetap dapat dipakai walaupun POP draft task itu corrupt; test native merusak GCM fixture POP, memastikan button start tersedia dan ciphertext tidak berubah setelah retry read. Journal execution yang sendiri tidak terbaca tetap menahan mutation, karena hasil attempt lama tidak boleh diabaikan.
- Malformed root JSON (`false`,0,null,array/invalid JSON) tidak dianggap file absent. Metadata yang tidak didukung tidak ditimpa/dihapus. Keystore irrecoverable tetap perlu support; UI tidak menjanjikan decrypt setelah key hilang. Login ulang akun/environment asal dan retry read adalah recovery untuk error sesi/transient; **jangan clear app data/uninstall/reset key sebagai workaround**. Support memeriksa server/reconciliation dan mempertahankan ciphertext bila recovery belum dapat dilakukan.
- Detail yang sudah terbaca boleh bertahan setelah network failure. GET404/authorization denial tidak mempertahankan task/primary action lama. Local-storage error tidak disamakan dengan server/network error.
- Capture pending tidak ditimpa capture baru. Legacy Camera cancellation yang message-only ditangani; gallery cancellation memakai error code SDK terpasang. Failed acquisition menyimpan konteks asal, dengan explicit recover/cancel controls; evidence/draft selesai sebelumnya tidak dihapus.
