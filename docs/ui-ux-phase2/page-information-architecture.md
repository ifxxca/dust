# Phase 2 — page-by-page information architecture review

This is a new product hierarchy review of the 58 previously discovered task surfaces, not a repeat of route discovery. The existing task-first policy in [AGENTS.md](../../AGENTS.md) remains authoritative. Current page/component code, rendered web baselines, and existing capability/date contracts were consulted. Automated checks establish layout and interaction behavior; no user study was conducted.

Every row states the primary task, current hierarchy, redundant or misplaced information, and proposed disposition. “Retain” means no justified structural change in this review, not proof of user-tested usability. Native, disabled registration, and conditional verification limitations are explicit. Unrelated report/profile/auth changes are excluded from ownership and redesign credit.

## Embedded workflows and shared structure

Customer/schedule dialogs retain focused forms and their existing validation/draft recovery. Pickup creation remains a dialog from dashboards and a dedicated operations form; no extra step is introduced. Task execution/proof, handover verification, bulk assignment, JNE quick detail, source-evidence/rule/exception sheets, alias import/editor and report/configuration dialogs preserve their existing action and authorization contracts. They are reviewed within their owning task surfaces, not counted again as pages.

Shared sidebar/layout and compact monitoring header already make navigation and active date context available. This phase changes the overview/role-dashboard hierarchy, customer analytic server summary, task summary placement, and sender-name sync history. Existing shadcn Button/Card/Collapsible/Table and existing Tailwind tokens are retained. No new design system, chart library, route, endpoint, or backend rule is introduced.
